# Task: thêm chức năng cho UI

Please inspect the current NestJS JWT authentication implementation and modify **only the JWT signing/verification mechanism** from the current symmetric secret-based approach to an **asymmetric Public Key / Private Key approach using RS256**.

Do not modify unrelated authentication logic.

## Requirements

1. Inspect the current JWT configuration, including:

   * `JwtModule.register(...)`
   * `JwtModule.registerAsync(...)`
   * `JwtService.sign(...)`
   * JWT Strategy / Guard
   * `JWT_SECRET`
   * JWT-related environment variables

2. Determine the current JWT algorithm before making changes.

3. Replace symmetric JWT signing such as:

```ts
secret: process.env.JWT_SECRET
```

with RSA asymmetric signing:

```text
Private Key -> Sign JWT
Public Key  -> Verify JWT
```

Use:

```ts
algorithm: 'RS256'
```

4. Configure NestJS JWT approximately as follows, adapting it to the existing project structure:

```ts
JwtModule.registerAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => ({
    privateKey: configService
      .getOrThrow<string>('JWT_PRIVATE_KEY')
      .replace(/\\n/g, '\n'),

    publicKey: configService
      .getOrThrow<string>('JWT_PUBLIC_KEY')
      .replace(/\\n/g, '\n'),

    signOptions: {
      algorithm: 'RS256',
      expiresIn: '1h',
    },

    verifyOptions: {
      algorithms: ['RS256'],
    },
  }),
});
```

Preserve the project's existing token expiration configuration instead of changing it unnecessarily.

5. Existing token creation code such as:

```ts
const accessToken = this.jwtService.sign({
  sub: user.id,
  email: user.email,
});
```

should continue to work, but the token must now be signed using the RSA **Private Key**.

6. JWT verification must use the corresponding RSA **Public Key**.

7. Add/update environment configuration:

```env
JWT_PRIVATE_KEY=
JWT_PUBLIC_KEY=
```

Support PEM values containing escaped newlines (`\n`) when stored in `.env`.

8. Do not commit real RSA private keys into the repository.

Update `.env.example` only with placeholders.

9. Explicitly restrict JWT verification to:

```ts
algorithms: ['RS256']
```

Do not silently allow both `HS256` and `RS256`.

10. Do not change:

* login business logic
* password validation
* user repository logic
* controllers
* API response structure
* unrelated authentication behavior

## Important Security Note

This change is **not JWT payload encryption/decryption**.

RS256 uses asymmetric cryptography for:

```text
Private Key
    ↓
Sign JWT
    ↓
JWT
    ↓
Verify Signature
    ↓
Public Key
```

JWT payload remains readable/decodable.

The purpose of the Public/Private Key pair is to ensure that only the holder of the Private Key can generate a valid JWT, while services holding the Public Key can verify it.

## Validation

After implementation:

* verify login can still generate an access token;
* verify the generated token uses `alg: RS256`;
* verify a token signed with the configured Private Key is accepted;
* verify a token signed with another Private Key is rejected;
* verify an HS256 token is rejected;
* verify an expired or modified token is rejected;
* run the project's relevant build/tests.
