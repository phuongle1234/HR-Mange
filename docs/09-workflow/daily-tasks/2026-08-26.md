# Task: 

# SPEC — Employee, Invitation User và Organization
 
## 1. Mục tiêu
 
Thực hiện bổ sung và hoàn thiện các chức năng cho các module sau:
 
- Employee
- Organization
- Organization Type
- Auth / User Invitation
- Invitations
 
Mục tiêu chính:
 
1. Employee hỗ trợ Create / Update / Delete hàng loạt tương tự Organization Type.
2. Employee có quan hệ FK với Organization.
3. Employee Create/Edit thao tác nhiều record theo layout dạng table.
4. Organization field trong Employee sử dụng `react-select`.
5. Employee List có chức năng Invite User từ các item đã được chọn.
6. Tạo module mới `invitations`.
7. Xây dựng đầy đủ flow mời user qua email theo hướng event-driven, bất đồng bộ.
8. Email local có thể kiểm tra bằng Docker.
9. Thiết kế kiến trúc email để sau này có thể chuyển sang Mailjet hoặc SMTP thật.
10. Organization Create/Edit modal được kết nối API thật và lưu được dữ liệu.
11. Organization có FK với Organization Type.

## 5. Employee Create/Edit — Bulk Table Editor
 
### 5.1. Mục tiêu
 
Màn hình Employee Create/Edit không thao tác với một Employee duy nhất.
 
Màn hình phải hỗ trợ thao tác nhiều Employee cùng lúc dưới dạng table.
 
Các thao tác:
 
```text
Create nhiều Employee
Update nhiều Employee
Delete nhiều Employee
```
 
### 5.2. Layout
 
```text
Employee Create / Edit
┌───────┬─────────────────────┬─────────────────────┬─────────────────────┐
│ Check │ Name                │ Email               │ Organization        │
├───────┼─────────────────────┼─────────────────────┼─────────────────────┤
│  ☑    │ [ Nguyen Van A ]    │ [ a@example.com ]   │ [ Engineering ▼ ]   │
│  ☑    │ [ Nguyen Van B ]    │ [ b@example.com ]   │ [ HR          ▼ ]   │
│  ☐    │ [ Nguyen Van C ]    │ [ c@example.com ]   │ [ Sales       ▼ ]   │
└───────┴─────────────────────┴─────────────────────┴─────────────────────┘
```
 
Mỗi `tbody > tr` đại diện cho một Employee record.
 
Mỗi cell chứa input/select tương ứng để user chỉnh sửa trực tiếp.
 
### 5.3. Table Header
 
`thead` có checkbox `Check All`.
 
Khi chọn:
 
```text
Check All = true
```
 
thì toàn bộ record hiện tại được checked.
 
Khi bỏ chọn:
 
```text
Check All = false
```
 
thì bỏ checked toàn bộ record.
 
Nếu chỉ một phần record được chọn, checkbox header phải hỗ trợ trạng thái:
 
```text
indeterminate
```
 
### 5.4. Table Body
 
Mỗi row tương ứng với một Employee.
 
```text
Employee Row
    |
    +-- checked
    +-- name
    +-- email
    +-- organizationId
    +-- các Employee field hiện có
```
 
Các field text sử dụng input trực tiếp.
 
### 5.5. Organization Field
 
Thêm column:
 
```text
Organization
```
 
Organization phải sử dụng:
 
```ts
import Select from 'react-select';
```
 
Ưu tiên:
 
```text
react-select@5.10.2
```
 
Trước khi implementation, kiểm tra compatibility với React 19 thực tế trong project bằng:
 
```bash
npm view react-select peerDependencies
npm install
npm run build
```
 
Nếu package manager của project không phải npm thì sử dụng command tương ứng.
 
Không tự ý downgrade React.
 
Nếu `react-select` gây peer dependency/build/runtime incompatibility thực tế với React 19, report rõ vấn đề trước khi thay bằng thư viện khác.

## 10. Employee → User Relationship
 
Nếu Employee chưa có FK tới User, bổ sung:
 
```text
Employee
   |
   | userId
   v
User
```
 
Conceptual Prisma:
 
```prisma
model Employee {
  id     String  @id
  userId String? @unique
 
  user User? @relation(
    fields: [userId],
    references: [id]
  )
}
```
 
Mục tiêu business:
 
```text
employee.userId == null
```
 
nghĩa là Employee chưa có User Account.
 
Khi Employee accept invitation:
 
```text
employee.userId = createdUser.id
```

## 11. Step 1 — Lấy Employee hợp lệ

```text
Employee
WHERE id IN employeeIds

```
 
Concept:
 
```ts
where: {
  id: {
    in: employeeIds,
  },
  userId: null,
}
```
 
Ngoài `userId = null`, phải kiểm tra Employee có email hợp lệ.

## 13. Invitation Token
 
Mỗi Employee phải có một token riêng.
 
```text
Employee A
   ↓
Token A
   ↓
Invitation A
 
Employee B
   ↓
Token B
   ↓

```
 
Token phải tạo bằng cryptographically secure random, ví dụ Node.js `randomBytes(...)`.
 
Không dùng `Math.random()`.
 
Raw token chỉ dùng để build URL.
 
Database chỉ lưu `tokenHash`.

## 23. Production Reliability
 
Nếu chỉ dùng NestJS EventEmitter thì event là in-memory.

```text

Event chưa được xử lý

Mail không được gửi
```

```text
BullMQ
Redis
Outbox Pattern
```
