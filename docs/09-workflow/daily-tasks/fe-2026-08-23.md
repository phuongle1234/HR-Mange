# 3. Organization data model

Frontend sử dụng model:

```ts
export interface OrganizationStage {
  uiId: number;
  parentUiId: number | null;

  // DB ID, hiện tại chưa bắt buộc.
  // Sau này API trả về.
  id?: number;

  code: string;
  name: string;

  type: OrganizationType;

  description?: string;

  manager?: {
    id?: number;
    name: string;
    avatar?: string;
  };
}

export enum OrganizationType {
  COMPANY = 'COMPANY',
  BRANCH = 'BRANCH',
  DIVISION = 'DIVISION',
  DEPARTMENT = 'DEPARTMENT',
  TEAM = 'TEAM',
}
```

---

# 4. Quy tắc quan trọng về uiId

`uiId` là ID do frontend tạo ra.

Không sử dụng UUID.

Không sử dụng `crypto.randomUUID()`.

Không sử dụng database ID để làm `uiId`.

Quy tắc:

```ts
newUiId = Math.max(...allUiIds) + 1;
```

Nếu stage chưa có record:

```ts
newUiId = 1;
```

Ví dụ:

```text
uiId   parentUiId   name
1      null         ABC Corp
2      1            Khối Công Nghệ
3      1            Phòng Nhân Sự
4      2            Backend
5      2            Frontend
```

Cây:

```text
ABC Corp
├── Khối Công Nghệ
│   ├── Backend
│   └── Frontend
│
└── Phòng Nhân Sự
```

---

# 5. Quy tắc parentUiId

`parentUiId` là ID của parent do frontend tạo.

Root:

```ts
parentUiId: null
```

Child:

```ts
parentUiId: parent.uiId
```

Khi user click `[+]` trên node:

```ts
parentUiId = selectedOrganization.uiId;
```

Nếu đang chọn:

```text
Khối Công Nghệ
uiId = 2
```

và thêm:

```text
Backend
Frontend
QA
```

thì tạo:

```ts
[
  {
    uiId: 4,
    parentUiId: 2,
    name: 'Backend'
  },
  {
    uiId: 5,
    parentUiId: 2,
    name: 'Frontend'
  },
  {
    uiId: 6,
    parentUiId: 2,
    name: 'QA'
  }
]
```

# 18. Delete algorithm

Implement function:

```ts
function removeOrganizationTree(
  uiId: number,
  organizations: OrganizationStage[],
): OrganizationStage[]
```

Algorithm:

1. Tìm node có `uiId`.
2. Đánh dấu node.
3. Tìm tất cả node có `parentUiId` bằng node đó.
4. Đệ quy tìm descendants.
5. Remove toàn bộ descendants.
6. Trả về stage mới.

Không mutate trực tiếp state hiện tại.

Ưu tiên immutable update.

# 31. Important business rules

### Note 1

Chỉ root Organization mới có:

```ts
parentUiId = null
```

### Note 2

Một Organization chỉ có một parent.

### Note 3

Một Organization có thể có nhiều children.

### Note 4

Không được tạo cycle.

Ví dụ không được:

```text
A
└── B
    └── C

C → A
```

Trong task hiện tại không có Move action, nhưng helper function nên thiết kế để sau này có thể validate cycle.

### Note 5

`uiId` luôn unique trong stage.

### Note 6

Xóa parent phải xóa toàn bộ descendants.

## Node Actions

Mỗi Organization Node có 3 vùng/action:

1. [+]
   → Mở Add Organization Modal.
   → Các Organization mới sẽ có parentUiId = uiId của node hiện tại.

2. [x]
   → Xóa node ngay lập tức.
   → Không confirmation.
   → Đồng thời xóa toàn bộ descendants.

3. Click vào body của Node
   → Mở Edit Organization Modal.
   → Form được populate bằng dữ liệu hiện tại.
   → Cho phép chỉnh sửa
   → Parent Organization chỉ hiển thị readonly.
   → Không thay đổi uiId.
   → Không thay đổi parentUiId.
   → Save sẽ update Frontend Stage.

# 35. Coding guideline

Ưu tiên:

* Component nhỏ.
* TypeScript strict.
* Không dùng `any` nếu không cần thiết.
* Không mutate state trực tiếp.
* Tách tree logic khỏi React Flow.
* Tách modal khỏi Node.
* Tách API abstraction khỏi UI.
* Dùng reusable functions cho tree operations.
* Dùng `useMemo` cho nodes/edges/layout khi phù hợp, lưu ý có debound khoảng 200 để thư viện không bị ảnh hưởng
* Không hard-code Organization data trong component.
* Có mock initial data riêng nếu cần demo.
* Code phải dễ thay thế mock stage bằng React Query/API sau này.

Cuối cùng, hãy implement hoàn chỉnh màn hình theo specification trên và đảm bảo ứng dụng build/type-check thành công.
